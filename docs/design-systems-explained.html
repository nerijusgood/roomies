Before we build one

A design system is the rulebook for how your app looks and behaves.

It holds every color, size, font and component in one place, with a name and a rule for each. Screens use those names. They do not invent their own values.

How it is built

Four layers. Each layer uses only the layer under it.

Tokens

A token is a named design value. You write the name, not the raw value.

--accent: #F07A2B--radius: 24px--butter / --butter-ink

All examples on this card come from the Roomies code today: src/styles/theme.css and src/components/ui/index.tsx.

How it works

Change one token. Every screen follows.

--accent
Active nav tab
Done"All done" state
Progress ring
Focus outline

Without tokens, the same orange is typed into many files. To change it, you search and hope you found every copy. With tokens, you edit one line.

Dark mode works the same way. You give each token a second value for dark, and the whole app switches.

What is the point

Six things you get from it

Consistency

The same thing looks the same on every screen. Users learn the app faster.

Speed

A new screen is assembled from parts that exist. You make fewer small decisions.

Safe change

A rebrand or a dark mode is a token edit, not a rewrite of every file.

Shared language

Designers, developers and Claude say "butter tile" and mean the same thing.

Accessibility in one place

You test text contrast once per token pair, for example --mint with --mint-ink.

Reuse outside the app

Pitch decks, landing pages and social posts can use the same look without copying code.

What "extract" means

Five steps from code to a design system

  1. 01

    Inventory

    Scan the code for every color, font size, radius, spacing value and component.

  2. 02

    Merge

    Combine values that are almost the same. Eleven font sizes can become six.

  3. 03

    Name

    Give each value a name for its job, for example --done, not --green.

  4. 04

    Document

    Show each token and component with a short rule for when to use it.

  5. 05

    Publish

    Put it in one page that people and tools can read. Then point the code back at it.
